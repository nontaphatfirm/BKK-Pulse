> [!IMPORTANT]
> **Critical Technical Edge Cases Already Known in V1.0:**
> 1. **Camera `395` (`แยกเสาชิงช้า`) Resolution:** 99 cameras are `352 x 288` px, but valid frames of Camera `395` are **`348 x 261` px** (while its white error frames were `400 x 266`). Always read `img_width`, `img_height` per camera instead of hardcoding `352 x 288`.
> 2. **Morning Outage on `2026-08-27` (`06:00-08:50`):** All 100 cameras suffered a central acquisition outage (only ~`7,438` raw / `7,229` valid frames that day; Cam `432` & `1804` showed Rainbow test bars, Cam `150` froze overnight, others emitted white timeout frames).
> 3. **OSD Dates (`1970-01-01`):** Do **not** trust text printed inside the image corner; true timestamps are already extracted from raw filenames and stored in `timestamp` / `clean_filename`.

## 1. What Has Already Been Cleaned in `V1.0`

### 1.1 Image-Level Cleaning (5-Stage Automated Image Quality Gate)

From **`61,319` raw `.jpg` frames**, `V1.0` filtered out **`1,109` defective frames (`1.81%`)** and kept **`60,210` verified frames (`98.19%`)** inside `cctv_images/`:

| Gate | Output `status` | Detection Rule in `clean_dataset_v1.py` | Action Taken | Filtered Count |
| :---: | :--- | :--- | :--- | :---: |
| **Gate 1** | `white_error` | `file_size < 2,000 bytes` OR `brightness_mean == 255.0` | Excluded from `cctv_images/` (blank HTTP timeout images clustered `07:15-08:45`) | **504** |
| **Gate 2** | `no_signal_error` | `file_size == 8,782` OR (`8,700 <= file_size <= 8,900` and `127.5 <= brightness_mean <= 128.5` and `contrast_std >= 111.0`) | Excluded `gst-launch-0.10` Rainbow color bars (`Cam 432`: 17, `Cam 1804`: 16) | **33** |
| **Gate 3** | `corrupt_color` | **Gray P-Frame:** `127.0 <= brightness_mean <= 132.0` and `contrast_std < 16.0` (**11**); **Green Screen:** `(g_mean - r_mean > 40.0)` and `(g_mean - b_mean > 40.0)` (**8**) | Excluded severe YUV / missing I-Frame frames *(normal dark-blue night frames preserved)* | **19** |
| **Gate 4** | `frozen` | Pixel-wise `mad_from_prev == 0.0` vs. the latest non-error frame of the same `cam_id` | Excluded stalled duplicate frames to prevent double-counting vehicles | **553** |
| **Gate 5** | `valid` | Strict timestamp parse from raw filename `_YYYYMMDD_HHMMSS.jpg` + Unicode-safe copy | Kept in `cctv_images/` with ASCII name `<cam_id>_<YYYYMMDD_HHMMSS>.jpg` | **60,210** *(Valid)* |

Additional image-level processing completed in `V1.0`:
- **ASCII Filename Standardization:** Raw filenames contained Thai Unicode strings that failed `cv2.imread()` on Windows; all clean files now use `<cam_id>/<cam_id>_<YYYYMMDD_HHMMSS>.jpg`, while original paths stay archived in `filename` and `raw_rel_path`.
- **Non-Destructive Artifact Warnings (`quality_warning`):** `32` valid images with partial bottom-strip glitches remain in `cctv_images/` and are flagged for review:
  - `partial_gray_pframe` (`24` frames): `cam_id = 169` (`19` frames), `cam_id = 206` (`5` frames).
  - `partial_green_screen` (`8` frames): `cam_id = 500` (`7` frames), `cam_id = 630` (`1` frame).
- **Precomputed Visual Telemetry:** Every row in `image_quality_manifest` already includes `brightness_mean`, `contrast_std`, `glare_ratio` (pixels `> 245`), `r_mean`, `g_mean`, `b_mean`, `gray128_ratio`, `neon_green_ratio`, `mad_from_prev`, and `frozen_ref_timestamp` for downstream rain/visibility analytics.

### 2.2 Step-by-Step Verification Checklist (Per Camera)

For each `cam_id` in your assigned Batch:
1. **Open Sample Images (Day & Night):** View at least 2 daytime frames (`~10:00-15:00`) and 2 evening/night frames (`~19:00-20:30`) in `cctv_images/<cam_id>/`.
2. **Verify Coordinate vs. Label Match:** Paste `lat, lon` from `cctv_info_cleaned.csv` into Google Maps and verify `location_th`, `location_detail_th`, `location_en`, `location_detail_en`, `district`, and `corridor`.
3. **Verify Flow Direction & Pairs:** Watch headlight/taillight direction at night (`19:00+`) to confirm whether `direction` (`Inbound` / `Outbound` / `None`) and `pair_id` / `pair_type` reflect actual road geometry.
4. **Inspect Missed Image Defects (Human Visual Audit):**
   - Look for severe lens obstruction (tree branch/bird/truck blocking 100% of frame), pitch-black unlit outage frames, half-corrupted bottom bands (`quality_warning != "none"`), or stalled scenes where only background compression noise changed (`MAD > 0` slightly even though traffic stood still / OSD time didn't change).
   - **Important:** Do **NOT** delete rainy, wet-road, or glare-heavy frames just because image contrast drops -- Task `04_ds_traffic_analytics` explicitly uses those frames to detect visual rain and measure resilience!
5. **Group Decisions Needed Before Finalizing `V2.0`:**
   - Decide whether the `32` `quality_warning` frames (`169`, `206`, `500`, `630`) distort YOLO/CV detections enough to exclude, or remain usable.
   - Inspect `cam_id = 370` & `371` (`309` low-contrast frames with `contrast_std < 20`) to verify whether they are blurry sensor hardware issues vs. usable night scenes.

## 3. Version History Rules & Change-Logging Workflow (For Team & Final Report)

Every data-cleaning edit after `V1.0` **must be documented** so teammates know what changed and we have complete Before -> After evidence for the final project report.

### 3.1 Versioning Convention
- **`V1.0` (Current Baseline):** Initial automated 5-Gate image cleaning + curated metadata repair (`61,319 -> 60,210` valid images).
- **`V1.1`, `V1.2`, ... (Patch Versions):** Metadata corrections from Batch 1-6 peer QA (`location_*`, `direction`, `pair_id`) or targeted frame exclusions / threshold tweaks on the existing `V1` dataset.
- **`V2.0` (QA-Verified Release):** Locked dataset after all 6 Batches pass verification and team consensus is reached on `quality_warning` / edge-case cameras (`370`, `371`, `169`, `206`, `500`, `630`).

### 3.2 Mandatory Rules for Anyone Cleaning or Modifying Data

1. **Never modify `Dataset/` raw files:** Always preserve original raw images and `Dataset/cctv_info.csv`.
2. **Never edit `.parquet` / `.csv` files manually without updating reproducible code:**
   - Metadata fixes go into `CAMERA_CURATION` inside [`00_data_cleaning_and_qa/src/clean_dataset_v1.py`](../00_data_cleaning_and_qa/src/clean_dataset_v1.py), then re-run:
     ```bash
     python 00_data_cleaning_and_qa/src/clean_dataset_v1.py --skip-copy
     ```
   - Image filter changes go into Gate thresholds / exclusion lists in the cleaning script (or save explicit exclusion lists) before re-generating manifests, and always validate afterward with `python run_pipeline.py --check-contract`.
3. **Every Change Must Be Recorded in [`CLEANING_CHANGELOG.md`](CLEANING_CHANGELOG.md):**
   - If you edited via Google Drive review (no Git setup yet), write your findings & requested fixes directly into [`CLEANING_CHANGELOG.md`](CLEANING_CHANGELOG.md) (or add rows to the Change Ledger table) with **Who, Date, Version, `cam_id` / filenames, Issue Found, Action Taken, Before -> After Count/Value**.
   - If you run `clean_dataset_v1.py`, this `README.md` and `CLEANING_CHANGELOG.md` remain preserved unless `--overwrite-readme` is explicitly specified.
4. **Update Verification Checkboxes in GitHub:** Once you finish checking your batch, mark `[x]` in [`00_data_cleaning_and_qa/CAMERA_AUDIT_CHECKLIST.md`](../00_data_cleaning_and_qa/CAMERA_AUDIT_CHECKLIST.md).
